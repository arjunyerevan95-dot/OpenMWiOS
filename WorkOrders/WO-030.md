## Objective

Correct the reproducible Seyda Neen exterior rendering defects and make the existing iOS touch controls meaningfully user-customizable.

This order has two independently reviewable tracks:

1. **Renderer correctness**
   - correct opaque foliage/hanging-moss texture cards;
   - correct the white/blank distance regions, disconnected distant silhouettes, and sharp blue horizon/cutoff band;
   - keep foliage alpha/cutout and distance/fog/culling/paging/clipping as separate causal paths unless evidence proves convergence.
2. **Touch-control customization**
   - provide an on-device editor for repositioning and resizing the fixed touch controls;
   - provide a persistent opacity setting;
   - make the default idle icon opacity approximately 20% (approximately 80% transparent), with a restrained but visible pressed-state indication;
   - provide a safe reset to the Android-derived default layout.

The tracks must have separate causal/design notes, focused tests, and commits. A renderer result must not conceal an incomplete control editor, and touch UX work must not be used to broaden renderer changes.

## Established facts

### Renderer

- The accepted baseline reaches a textured, lit full-screen world, indoor play, and Seyda Neen exterior traversal on a physical iPhone.
- Maximum OpenMW view distance improved coverage but did not resolve opaque foliage cards, white/blank distance regions, disconnected distant silhouettes, or the sharp blue horizontal band. DEC-006 therefore rejects low view distance as a complete explanation.
- The supplied screenshots establish symptoms, not a responsible layer.
- Direct source exposes distinct state paths that require verification:
  - NIF material properties reach OSG alpha state through `components/nifosg/nifloader.cpp`;
  - OpenMW's shader visitor converts alpha-test requirements into shader defines/uniform state and disables deprecated fixed-function alpha test for the converted path;
  - compatibility object shaders apply `alphaTest(..., alphaRef)`;
  - OpenMW view distance and weather feed `RenderingManager`, `FogManager`, `StateUpdater`, camera projection/culling, sky, and terrain/scene loading;
  - GL4ES also contains fixed-pipeline alpha/fog emulation, but its participation in the observed draws is not yet proven.
- Water appearance improved when the user enabled its shader effects. Water is a regression check, not a currently proven defect.
- Reduced render scale `0.58`, noisy `ColorMaski` warnings, and the one transient red block remain separate, deferred observations unless evidence directly makes one causal to an authorized symptom.

### Touch controls

- `ios/openmw_ios_touch_model.hpp` currently creates one fixed Android-derived safe-area layout for twelve action buttons plus movement/look regions.
- `ios/openmw_ios_touch_controls.mm` currently rebuilds that default layout and contains no persistent customization/editor path.
- Current icon draw alpha is `0.64` idle and `0.95` pressed, which is substantially more opaque than requested.
- The WO29 correction gives the process-lifetime non-ARC icon cache explicit ownership. That ownership invariant must remain intact.
- Existing movement, look, action dispatch, GUI passthrough, and gameplay-mode behavior are qualified foundations and must be refined rather than replaced.
- Codebase Memory may incompletely represent Objective-C++ `.mm` paths. Graph results are navigation aids; checked-out source is authoritative.

### Phase 3 - Persistent on-device touch editor

Implement a versioned customization model and an on-device editing experience against the existing touch architecture.

Required user-facing behavior:

1. **Entry is a long-press on the existing Menu/Pause touch button**, matching the requested Serious Sam-style interaction. Use a deliberate threshold in the `0.6`-`1.0` second range and record the exact value.
2. A normal short tap on Menu continues to dispatch the ordinary Pause/Menu action. The implementation must defer that action long enough to distinguish the gesture: once the long-press threshold is crossed, the pending Pause action is cancelled and no Pause down/up event may leak into SDL/OpenMW.
3. Long-press entry follows the Menu button's current saved bounds, including after that button has been moved or resized. Menu must retain a safe minimum size and may never be hidden or moved outside the safe area, so editor recovery remains possible.
4. Edit mode appears directly over the current game view and is visually unmistakable. Every editable fixed icon shows a selection/bounds ring and resize affordance; the movement control shows its adjustable radius.
5. Dragging a control body repositions it. Dragging its resize affordance changes its size. Selection/highlight must identify which action is being edited without requiring icon recognition alone.
6. Edit mode suppresses all SDL/OpenMW action, mouse, movement, and look dispatch. Moving/resizing a control must never attack, jump, open a menu, move the player, or turn the camera.
7. Every fixed action icon, including Menu itself, can be repositioned and resized. The movement-control radius must also be adjustable without breaking its floating-origin behavior.
8. A compact editor toolbar provides global opacity, `Done`, `Reset`, and `Cancel`:
   - opacity previews immediately while editing;
   - `Done` saves and exits;
   - `Reset` restores the Android-derived safe-area layout and nominal `0.20` idle opacity, with an explicit confirmation or equally safe undo path;
   - `Cancel` restores the complete pre-edit profile and exits without persisting changes.
9. Global idle opacity is adjustable. Its default is nominally `0.20`; pressed feedback may temporarily rise above idle but must remain visually restrained. Record the exact default, pressed value/rule, and clamp range.
10. The saved profile persists across force-quit/relaunch. Stored positions use safe-area-relative normalized coordinates or an equivalently rotation/device-independent representation. Layout rebuilding must clamp controls fully inside the current safe area and preserve usable hit targets.
11. Persistence is versioned, validates/clamps malformed values, and uses a logical app-local store. It must not contain or depend on a container UUID or absolute sandbox prefix.
12. GUI-mode passthrough remains intact outside visible controls/editor affordances. Gameplay movement, look, simultaneous movement + look, action dispatch, and input release on mode changes remain intact.
13. The non-ARC icon cache continues to own every cached `UIImage`; no new autorelease-lifetime dependency is introduced.

The worker may choose the exact native drawing/widgets for the editor after direct-source reconnaissance, but not its entry gesture or the interaction contract above. A separate settings-screen-only entry, hidden text configuration, or hard-coded alpha change does not satisfy this order.

Required tests include:

- profile defaulting, versioning, malformed-data fallback, clamping, save/load round trip, and reset;
- normalized layout resolution across at least three representative landscape sizes/safe-area shapes;
- per-button movement and resize bounds, movement-radius bounds, and hit testing after customization;
- edit-mode input suppression and normal-mode ownership/action invariants;
- Menu short-tap versus long-press gesture arbitration, including cancellation before SDL dispatch;
- `Cancel` rollback and safe `Reset` behavior;
- source/build checks preserving the WO29 icon ownership correction;
- the existing touch and aggregate iOS validation suites.

## Prohibited changes

- OpenMW, OSG, GL4ES, SDL, MyGUI, or other dependency revision changes.
- Broad renderer replacement, Metal migration, global feature disablement, or unexplained shader/state hacks.
- Forcing maximum viewing distance, disabling fog, replacing intended scene content with a background color, forcing all materials transparent/opaque, or disabling alpha-tested content as a visual workaround.
- Water tuning, reduced-scale `0.58` correction, transient red-effect work, `ColorMaski` cleanup, performance tuning, or cache redesign unless one is directly proven to be the earliest cause of an authorized symptom. If so, stop for orchestrator review before expanding materially.
- Changes to fullscreen/native-scale presentation, WO27 data discovery, signing/provisioning, bundle identity, action mappings, icon artwork, or unrelated application lifecycle behavior.
- A customization implementation that requires manual editing of configuration files or absolute container paths.
- Replacing the existing touch ownership/action foundation, adding unrelated actions, or swallowing unrelated GUI touches.
- Full Qualification, CI/cache redesign, unrelated cleanup, or modification of canonical ControlPlane files by the worker.

## Acceptance criteria

WO30 succeeds only when all applicable criteria are met:

1. R1 and R2 each have a source-verified causal model, or the unresolved path is explicitly reported without a speculative correction.
2. Corrected foliage assets preserve transparent cutouts without opaque rectangular cards at the qualified exterior viewpoints.
3. Corrected distance presentation removes the large unexplained white/blank regions and sharp blue cutoff band at the qualified viewpoints while respecting user-selected viewing distance and producing a coherent fog/sky/horizon transition.
4. Renderer corrections are minimal, deterministic, covered by focused tests, and preserve the accepted indoor/UI/fullscreen/water/runtime baseline.
5. Long-pressing the current Menu button enters the on-device editor without dispatching Pause; short-tapping it retains normal Menu/Pause behavior. The editor permits persistent per-control repositioning/resizing, movement-radius adjustment, opacity adjustment, safe reset, and cancel/rollback without manual file edits.
6. Default idle opacity is nominally `0.20`, pressed feedback remains restrained, and the exact values/ranges are recorded.
7. Customized profiles survive relaunch, remain safe-area correct across representative landscapes, and fail safely on corrupt/old data.
8. Edit mode emits no gameplay input; normal movement/look/action/multitouch/GUI-passthrough behavior remains functional.
9. WO29's icon ownership correction and WO27's runtime data path remain intact; no native crash, watchdog, or jetsam appears in the final matrix.
10. CI/build budget and prohibited-change limits are respected, and all claims are backed by compact evidence.

A result that proves and corrects only one renderer path, or completes only one major track, is a valid **PARTIAL / STOPPED** worker result. It is not permission to reinterpret the remaining scope or start another build/work order.

## Stop conditions

- **A - Baseline/control-plane conflict:** issued baseline, ACTIVE transition, or canonical-file ownership is inconsistent. Stop before source changes.
- **B - Renderer cause unproven:** bounded diagnostics cannot locate the earliest invalid R1 or R2 state. Preserve the comparison and stop rather than guess.
- **C - Dependency revision required:** correction requires updating a pinned dependency or undertaking broad upstream migration. Stop with source evidence.
- **D - New renderer boundary:** evidence implicates water, reduced-scale presentation, a transient effect, generalized performance, or an unrelated graphics path. Preserve and stop for amendment review.
- **E - Touch architecture expansion:** requested outcomes require action remapping, an unrelated settings-system redesign, or replacement of the input foundation. Stop with the smallest source-backed proposal.
- **F - Regression/crash:** data path, fullscreen, indoor/UI rendering, water, action dispatch, or lifecycle regresses, or any native crash/watchdog/jetsam occurs. Capture evidence and stop.
- **G - Build budget exhausted:** do not run another build. Report the exact remaining device/CI question.
- **H - Qualified success:** both tracks meet the acceptance criteria. Report and stop; do not begin follow-up polish.
