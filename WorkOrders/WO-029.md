## Objective

Capture authoritative iOS crash or termination evidence for the rejected WO28 candidate, classify the three observed failure paths independently, prove a source-level causal model, and apply a correction only when the evidence supports a bounded change.

The observed paths are:

1. intermittent immediate launch-time hard crash, sometimes repeated before a later launch reaches the menu;
2. immediate hard crash after selecting `New Game` from a successfully reached menu;
3. immediate hard crash after activating any tested touch-overlay button from a successfully reached menu.

Do not claim that these paths converge unless matching crash signatures, termination evidence, or a directly verified source mechanism proves convergence.

## Authorization boundary

This work order authorizes evidence collection, symbol/debug artifact preparation, source tracing, focused diagnostics, a proven bounded crash correction, focused regression tests, and the limited CI/device validation defined below.

It does not authorize broad touch redesign, renderer work, UX opacity changes, speculative signing changes, or unrelated cleanup.

Worker authority remains limited to execution and evidence:

- write execution records only under `Evidence/WO-029/`;
- do not modify `Documentation/CURRENT_STATE.md`, canonical `WorkOrders/`, or durable `Decisions/`;
- do not reinterpret or amend this work order from user feedback;
- if feedback implies changed scope, preserve it as evidence and stop for orchestrator review;
- stop after the completion/blocker report and await orchestrator review.

## Established facts

- WO27 is the highest accepted runtime baseline.
- WO28 candidate `1dc819c` compiled and packaged successfully in Fast Development run `32511443555`, artifact `OpenMW-iOS-fast-30` (artifact ID `9457442141`).
- The existing production artifact uploads the unsigned IPA and compact diagnostics, but the current Fast workflow does not upload a dSYM.
- The installed WO28 binary identity was not independently read back from the device.
- `ios/openmw_ios_touch_controls.mm` routes overlay actions through `setAction`, which lazily reaches `ensureVirtualController`, `SDL_JoystickAttachVirtualEx`, `SDL_GameControllerOpen`, and virtual button/axis dispatch.
- In GUI mode, the overlay accepts touches only on its visible GUI controls; other touches pass through to the underlying SDL/OpenMW UI. Therefore `New Game` is not automatically an overlay-action dispatch.
- Launch-time failure occurs before an explicit `New Game` or overlay action and must remain a separate path.
- Existing iOS milestone logging writes `Library/OpenMW/startup.jsonl`, but that log is not a substitute for an iOS crash/termination report.
- SideStore certificate invalidation and re-signing is environmental context only. No current evidence implicates signing, entitlements, dyld, provisioning, or installation state.
- Codebase Memory may omit Objective-C++ `.mm` functions. Use it for navigation, then verify every implementation fact against the checked-out source.

2. Create `codex/wo29-ios-crash-isolation` from the issued baseline.

4. Record pre-existing unrelated worktree changes without modifying, staging, or deleting them.

### Phase 1 — Candidate, binary, and symbol inventory

1. Re-verify run `32511443555`, artifact `9457442141`, executable/IPA hashes, artifact retention, and Full Qualification absence.
2. Inspect the artifact and production build settings for:
   - Mach-O UUID;
   - bundle identifier, version, and executable name;
   - available symbol table, link map, dSYM, and symbolication inputs;
   - pre-sign entitlements and provisioning state where present.
3. Determine the least invasive way to obtain an exact executable/dSYM/UUID set for a reproducible diagnostic candidate.
4. If the existing run cannot be symbolicated exactly, a diagnostic-only Fast build is authorized. It may add compact artifact outputs needed for symbolication, including dSYM, executable UUID, link map, hashes, and build identity. It must not change runtime behavior except for narrowly justified milestone diagnostics.
5. Preserve unsigned-CI identity separately from any post-sideload signing/provisioning identity. Do not assume they are identical.

### Phase 2 — Reproduction and authoritative crash capture

Prepare one concise device procedure; do not make the user infer logging steps.

For each path, record exact attempt counts and outcomes:

1. cold and repeated app launches before any menu action;
2. `New Game` after a successful menu launch;
3. each tested overlay control after a successful menu launch.

Collect, where available:

- the iOS `.ips` crash/termination report or equivalent device-console record;
- exception type/codes, termination namespace/reason, faulting thread, binary UUID, and top frames;
- exact installed bundle/version identity and signing/team/provisioning metadata exposed after sideload;
- relevant `startup.jsonl` tail with timestamps correlated to each attempt;
- a short reproduction matrix that keeps the three paths separate.

Distinguish native exception, abort/assert, dyld failure, watchdog termination, jetsam, deliberate exit, and disappearance without authoritative classification. “Hard crash” is an observation, not a mechanism.

### Phase 3 — Symbolication and causal model

1. Match each report's binary UUID to the exact executable and dSYM before trusting symbolicated frames.
2. Symbolicate the faulting thread and retain compact raw/symbolicated references under `Evidence/WO-029/`.
3. Compare signatures across the three paths. Record `CONVERGED`, `DISTINCT`, or `UNRESOLVED` for every pair, with the evidence supporting that classification.
4. Use Codebase Memory first for call/dependency reconnaissance, then inspect actual source directly.
5. Trace the implicated frames through iOS bootstrap/UIKit, SDL, OpenMW, and the touch bridge as applicable.
6. State the earliest proven invalid state or operation and explain why it produces the observed termination.
7. Treat signing, entitlement, dyld, provisioning, or installation state as causal only if authoritative evidence directly implicates it.

### Phase 4 — Conditional bounded correction

A source or workflow correction may begin only after Phase 3 establishes a causal model.

Authorized corrections are limited to:

- iOS bootstrap/lifecycle safety directly implicated by the evidence;
- iOS touch-overlay ownership, mode transition, SDL virtual-controller lifetime, or dispatch directly implicated by the evidence;
- diagnostic/symbol artifact production required to verify the candidate;
- focused tests reproducing the proven failure boundary.

If multiple distinct causes require unrelated corrections, fix only a single minimal common or highest-blocking boundary when clearly within scope; otherwise stop for orchestrator review rather than bundling independent fixes.

### Phase 5 — Qualification

1. Run focused local regression tests and the existing aggregate iOS validation suite.
2. Run no more than:
   - one diagnostic-only Fast build when exact symbols are unavailable; and
   - one corrected Fast Development build after local qualification.
3. Full Qualification must not run.
4. Cache architecture must not change. Record hits/misses; do not redesign caches.
5. For the corrected artifact, record CI run, commit, artifact ID, executable/IPA hashes, dSYM hash, and Mach-O/dSYM UUID match.
6. Controlled device validation must include:
   - ten consecutive launch attempts without native crash or unexplained termination;
   - at least three successful `New Game` transitions from a freshly reached menu;
   - every visible menu-mode overlay control and the early-game control set relevant to WO28;
   - movement, look, simultaneous movement + look, and one additional action;
   - WO27 automatic data discovery;
   - fullscreen/rendering/audio/scene-transition regression checks.

Device participation supplies execution evidence; it is not an amendment or approval gate. New user feedback outside these criteria must be recorded and escalated to the orchestrator.

## Acceptance criteria

WO29 succeeds only when all applicable criteria are met:

1. Exact source, CI artifact, executable, dSYM, and tested installed identity are correlated as far as the platform permits; every unresolved identity gap is explicit.
2. Each of the three observed paths has its own reproduction record and authoritative termination classification, or a documented attempt matrix proving the path did not reproduce.
3. Pairwise convergence/distinction claims are evidence-backed; no paths are merged by assumption.
4. The faulting thread is symbolicated against a matching UUID when a native crash exists.
5. The causal model is verified against checked-out source and identifies the earliest proven failure boundary.
6. Any correction is minimal, reviewable, within the authorized boundary, and covered by focused regression tests.
7. The corrected candidate meets the Phase 5 launch, `New Game`, overlay, early-game, data-path, and runtime regression checks without native crash, watchdog, or jetsam.
8. No prohibited subsystem changed, Full Qualification did not run, and no extra engineering scope was inferred from user feedback.

A completed classification that proves multiple independent causes outside the bounded-correction authority is a valid **PARTIAL / STOPPED** execution result, not permission to expand scope.

## Stop conditions

- **A — Identity mismatch:** crash binary UUID cannot be matched to the tested executable/dSYM. Stop before causal claims.
- **B — No authoritative termination evidence:** defined reproduction attempts complete without an `.ips`, device-console classification, or equivalent evidence. Stop with the exact collection gap; do not guess.
- **C — Signing/install boundary implicated:** dyld, code-signing, entitlement, provisioning, or installation evidence is causal. Preserve it and stop for orchestrator direction before material signing changes.
- **D — Distinct broad causes:** the paths prove to have unrelated causes requiring separate corrections. Classify them and stop rather than bundle them.
- **E — Cross-project/upstream change required:** a correction requires SDL/OpenMW dependency revision or broad upstream modification. Stop with source evidence.
- **F — Renderer/data-path regression:** stop immediately.
- **G — New crash or termination signature:** capture, classify, and stop unless it is directly within the already proven correction boundary.
- **H — Bounded success:** the corrected candidate meets all acceptance criteria. Stop and report; do not begin UX or renderer work.
