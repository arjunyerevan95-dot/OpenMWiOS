## Established evidence

### Physical symptom

At maximum view distance, the accepted screenshots show:

- large white or fog-colored blank regions beyond nearby rendered geometry;
- incomplete/disconnected distant silhouettes;
- a sharp blue horizontal horizon/cutoff band; and
- some improvement from maximum view distance, but no resolution.

WO33 corrected smoke/spell blending and visibly improved foliage alpha. Those paths are no longer the target of this order.

### Accepted R2 state

The accepted WO33 correction trace (session `9504FA5C-CF45-46D9-908E-2F1838B8B0B9`, SHA-256 `6D57F23FEE227608A5285BC52BB0AB386BB4E7ABEE7EB9F9787931E39E8B2C3B`) contains 96 R2 records:

- OpenMW exterior fog intent and OSG application agree at `start=2007.04`, `end=7168`, color approximately `0.960784,0.921569,0.878431,1`;
- GL4ES received the fog values;
- multiple late exterior programs applied the matching fog generation;
- the scene-camera clear color equals the exterior fog color;
- the active grid is `-3,-10,0,-7` with object paging disabled; and
- exterior cells `-3..-1` by `-10..-8` loaded.

One observed program lacked built-in fog locations, but it was not correlated to the defective pixels/geometry. Do not treat that program as the cause without new evidence.

### Projection/terrain mismatch candidate

The same trace records the physical projection:

- resolution `2868x1320`;
- aspect `2.17272727`;
- vertical FOV `60°`;
- near `1`;
- far/view distance `7168`;
- non-reversed Z; and
- terrain view distance `8276.89`.

Direct inspection of pinned OpenMW `f4bec41444214a7903bebd178389ca22ca13f646` establishes:

- `RenderingManager::updateProjectionMatrix` constructs the perspective using vertical FOV and aspect;
- it expands terrain view distance using only `1 / cos(verticalFov / 2)`;
- `RenderingManager::getWorldspaceChunkMgr` independently repeats the same aspect-unaware calculation for newly created terrain worlds;
- `Terrain::distance` computes Euclidean distance from the camera to a quadtree bounding box; and
- `DefaultLodCallback::isSufficientDetail` stops non-active-grid traversal when that radial distance exceeds the configured terrain view distance.

At 60° vertical FOV, the current multiplier is approximately 1.1547 regardless of landscape aspect. The camera frustum is substantially wider at aspect 2.1727. This is a strong causal candidate, not yet an accepted cause. The worker must derive the correct coverage relation from the actual projection and terrain-distance semantics before changing code.

## Acceptance criteria

1. the first invalid distance/horizon boundary is proven from the exact projection, terrain, and device evidence;
2. the correction is general, minimal, regression-covered, and affects only the proven coverage calculation;
3. both initial and runtime-update terrain paths use the corrected calculation;
