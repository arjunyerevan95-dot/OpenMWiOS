# WO-026 — Android-Derived Touch Controls Baseline

- Status: **completed — partial touch qualification**
- Issued baseline commit: `cf1d2fd1521bc4465709a56f1a387637d474b56f`
- Implementation commit: `8845e38349a356bb8dc3e496723a93c7ea39bf52`
- Qualified ending commit: `5c60db4c4f1ca5c135a0bea754496b7a2f1af3f1`
- Migration execution state: historical/completed; no further work authorized during migration

## Objective

Adapt the recent Android OpenMW touch-control architecture to iOS so movement, look, activation, core actions, and essential GUI interaction can be exercised through multitouch without regressing the qualified renderer.

## Effective scope

- Add an iOS touch overlay and touch-event bridge derived from the Android control semantics.
- Preserve full-screen native rendering, UI, audio, scene transitions, and external input paths.
- Qualify basic traversal and interaction only; defer visual polish, layout customization, exterior performance tuning, and unrelated renderer work.

## Completed steps

- Added device-agnostic touch layout, movement-stick, look-region, and gameplay buttons.
- Added bounded touch diagnostics and deterministic layout/input tests.
- Corrected an Objective-C++ production compilation issue without changing touch semantics.
- Produced and installed the Fast Development candidate.
- Demonstrated movement/look through the prison ship and into the Seyda Neen exterior.
- Preserved full-screen world rendering, UI, audio, and scene transitions.

## Qualification result

The primary traversal capability was materially achieved, but the Android-derived product behavior was only partially qualified:

- Movement: observed working.
- Look/camera: observed working.
- Ship-to-exterior traversal: observed working.
- Touch overlay: visible.
- Android layout/action fidelity: unresolved.
- Inventory: observed nonfunctional through the present mapping. The iOS path injects keyboard `B`, while the current OpenMW binding expects right mouse/controller `B` semantics.
- Simultaneous three-touch movement + look + action: not fully recorded.

## First incomplete boundary

Bring the layout and action bridge into faithful alignment with the recent Android implementation, beginning with the demonstrated Inventory/action mismatch. This work is **not issued as a numbered successor** and remains frozen pending orchestrator review.

## Prohibited changes

- Do not reopen qualified renderer, shader, FBO, viewport, VFS/MWUI, or data-path corrections without contradictory evidence.
- Do not infer exterior performance qualification from the observed traversal.
- Do not treat foliage, distance, or water observations as touch defects.
