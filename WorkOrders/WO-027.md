## Objective

Remove dependence on a persisted iOS sandbox UUID for the default Morrowind data location. Resolve the current application Documents directory at runtime and locate `OpenMW/Morrowind/Data Files` without worker, user, SideStore, usbmux, or configuration knowledge of `/var/mobile/Containers/Data/Application/<UUID>/...`.

## Scope

- Resolve the current Documents directory using the platform runtime API.
- Supply the default base-game path programmatically.
- Narrowly migrate only recognized legacy generated sandbox-UUID entries.
- Preserve unrelated `data=` entries, mod ordering, settings, and user configuration.
- Preserve the WO26 touch and qualified renderer baselines.

## Completed steps

- Traced the previous path owner and persistence mechanism.
- Implemented runtime construction of `Documents/OpenMW/Morrowind/Data Files`.
- Added narrow legacy-path recognition/migration rather than whole-config regeneration.
- Added 15 focused tests covering current Documents resolution, simulated container A/B changes, stale-entry migration, preservation, missing data, discovery, and idempotence.
- Completed Fast Development compilation, linking, bundle validation, and packaging.
- Installed the exact IPA and launched without manually editing `openmw.cfg` or supplying a container UUID/path.
- Reached the full-screen, textured, lit Jiub scene with the touch overlay intact.

## First incomplete evidence item

The post-install container UUID was not recorded because usbmux diagnostics were unavailable. The accepted test proves that no manual UUID/path input was needed, but it does not independently prove that the container UUID changed during that particular SideStore install. This is an evidence limitation, not an open implementation task.
