## Objective

Prove why the representative chimney-smoke draw still reaches `glDrawElementsCommon` with `glstate->enable.blend == 0` after the WO32 OSG routing candidate, then apply and qualify only the smallest correction supported by that event sequence.

This order continues the user's renderer priority. It addresses smoke/particle blending only. Foliage and distance/horizon rendering remain separate deferred boundaries.

## Authority and baseline

## Established facts

- The exact WO32 correction source compiled and ran; stale/wrong-source IPA is excluded.
- `textures/tx_smokealpha00a.dds` reaches program 9 as a translucent DXT5 target with standard alpha factors, disabled depth writes, and fragment discard/alpha output.
- Four corrected-candidate draws still record `blend=0`; visible smoke remains blocky.
- GL4ES `gl4es_glEnable` and `gl4es_glDisable` call `proxy_glEnable`; its `GL_BLEND` case mutates `glstate->enable.blend` when the requested value differs.
- The target draw diagnostic reads `glstate->enable.blend` in `glDrawElementsCommon` on the actual draw path.
- GL4ES can batch/intercept work through render lists before common draw execution.
- Source and patch presence do not prove that a conditional branch was compiled or exercised for the target draw.

6. Write an ordered causal model covering at least:

   - OSG and target draw use different GL4ES context/state objects;
   - render-list capture/replay restores or bypasses another blend value.

### Phase 1 — bounded target-gated transition tracing

Add diagnostic observation only. It must not mutate renderer state.

1. Preserve dynamic smoke identification; never hard-code texture ID 115 or program ID 9.
2. At the OSG blend-mode decision, record only bounded `GL_BLEND` events: requested value, cached/last-applied value, whether a GL call is issued, site identifier, graphics-context identity, and monotonic sequence.
3. At OSG `BlendFunc::apply`, record ordinary-versus-separate path and factors, without changing them.
4. At GL4ES `gl4es_glEnable`/`gl4es_glDisable` ingress for `GL_BLEND`, record sequence, requested value, previous/new `glstate->enable.blend`, `glstate`/context identity, thread identity, list pending/active state, FPE/shader-blend state, and whether the internal value actually changed.
5. Distinguish draw intake, render-list capture/replay, and `glDrawElementsCommon` execution. At the dynamically targeted smoke draw, emit the bounded recent blend-transition ring plus the draw's context/state identity.
6. Cap retained transition events and output. The file must distinguish no OSG call, no GL4ES ingress, later disable, context mismatch, and replay mismatch without startup log flooding.

## Acceptance criteria

WO33 succeeds fully when:

1. the exact linked OSG route and runtime call sequence are directly evidenced;
2. the first transition leaving the target draw at `blend=0` is proven, including context and render-list behavior;
3. the correction is minimal, causal, and regression-covered;
4. GL4ES records `blend=1` with the intended factors for representative smoke draws;
5. matching device evidence shows smoke cards blending rather than remaining opaque/blocky;
6. launch, HUD, native landscape presentation, and brief exterior traversal show no crash or obvious regression;
7. build, diagnostic, and scope budgets are respected.

A partial diagnostic acceptance requires criteria 1–2 with no speculative correction.
