## Objective

Determine whether the large exterior white/fog-colored gaps and sharp blue cutoff are primarily the consequence of running OpenMW's loaded-cell `TerrainGrid` with `distant terrain = false`, and determine whether a bounded higher view distance improves genuinely paged terrain without merely pushing the same defective boundary farther away.

Use the currently installed WO34 IPA for a configuration-only device experiment first. At 7168, change only the terrain-system selection and prove whether object paging activates. Higher view distances are authorized only after that same-distance comparison is trustworthy and stable.

If distant terrain materially corrects the gaps, the worker may make it a user-overridable iOS bundled default on the accepted engineering baseline and run one Fast build. Do not raise the iOS product's default view distance on one-device evidence; the existing large slider may expose higher user-selected values when distant terrain is enabled.

## Established evidence

### Device configuration

The preserved original WO35 settings file is 724 bytes with SHA-256 `EE80D8B9EFD9076070EFDF26902D4D5B881A0B54FE47626CE5C79DC4703743BA`. It contains:

```ini
[Camera]
viewing distance = 7168
```

It contains no `[Terrain]` section. The device now also retains the user's explicit WO35 preference:

```ini
[Fog]
sky blending = true
sky blending start = 0.8
```

Hold those Fog keys constant through every WO36 arm.

### Pinned-source behavior

Codebase Memory reconnaissance followed by direct inspection of pinned OpenMW `f4bec41444214a7903bebd178389ca22ca13f646` establishes:

- `files/settings-default.cfg` sets `distant terrain = false`, `object paging = true`, and `viewing distance = 7168.0`;
- `RenderingManager::getWorldspaceChunkMgr` selects `Terrain::TerrainGrid` when distant terrain and groundcover are false, but selects `Terrain::QuadTreeWorld` when distant terrain is true;
- the object-paging manager is attached inside that quadtree route when its existing default is true;
- `RenderingManager::updateProjectionMatrix` propagates viewing distance to camera far distance, shared uniforms, and terrain view distance;
- the settings window hides the large slider when distant terrain is false, leaving the 2500–7168 slider, and hides the small slider when distant terrain is true, leaving the 2500–81920 slider; and
- the current diagnostic records `active_grid=...;object_paging=0` at view distance 7168.

This makes distant-terrain activation the required first variable. Higher camera distance without paged terrain is not accepted as a causal test.

## Acceptance criteria

WO36 succeeds fully when:

1. same-binary Arm A/B evidence proves the exact terrain-system transition at constant view distance;
2. paging activation is proven by `object_paging=1` and the large-slider UI;
3. matching physical views materially improve at least one target defect and distinguish paging from higher-distance effects;
4. any product change is limited to a user-overridable iOS default enabling distant terrain, with default distance still 7168;
5. the exact product builds, packages, and activates paging without a manual terrain key;
6. the passing visual result reproduces without nearby rendering/input regression; and
7. no crash or obvious severe performance/memory regression occurs.

A valid partial success is that paged terrain fills the white gaps while the blue band or black silhouettes remain as separately classified boundaries. A valid falsification is that paging and bounded higher distance are proven active but leave the target unchanged or merely displaced, with no speculative product change.
