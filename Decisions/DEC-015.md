# DEC-015 — Accept WO35 falsification and test distant-terrain paging before raising view distance

- Status: **ACCEPTED**
- Date: 2026-08-25
- Applies to: WO-035 final review and WO-036 issuance

## Decision

Accept WO35 as a controlled same-binary configuration experiment. Accept its runtime activation proof and conclusion that OpenMW sky blending does not materially remove the sharp blue band or large fog-colored/white exterior cutoff on the physical iPhone.

Do not change the product default and do not advance the accepted engineering baseline. It remains `93f892dd0cf9834259b4cad2045ddb2ef9c53ed9`.

Permit the user to retain `sky blending = true` and `sky blending start = 0.8` in the device's own settings because the user prefers its angle/distance-dependent silhouette fading. This is local configuration state, not a qualified correction or canonical product behavior.

Issue WO36 as READY. It must test OpenMW's existing distant-terrain paging path at the same 7168 view distance before any higher-view-distance arm. Raising camera far distance while `distant terrain = false` is not an adequate renderer experiment because pinned source shows that state uses the loaded-cell `TerrainGrid` rather than the paged `QuadTreeWorld`.

## Accepted facts

- WO35's start directive and worker receipt are independently present in the worker session, although the separate ACTIVE bookkeeping commit was missed.
- Evidence commit `0b563307a32688a4aa5feddb6587f329f13c67b0` is evidence-only and directly based on the accepted engineering baseline.
- The test configuration changed only the two authorized sky-blending keys.
- Diagnostic session `AFEF6F3A-DD3C-402D-AF51-9D91BECAE505` proves `sky_blending=1` at view/far distance 7168 and the captured physical projection.
- All ten screenshot identities verify and visibly retain the blue/white target defects.
- No source, build, CI, or artifact was produced, and no canonical files were changed by the worker.

## Evidence limitation

WO35 did not assign fresh Arm A screenshot identities. Existing WO34 images and the same-binary identity provide historical baseline context, but the reported silhouette improvement is accepted only as a user observation/preference. The target falsification is stronger: a feature proposed to hide the cutoff was proven active while that cutoff remained clearly visible.

## Next bounded hypothesis

The preserved original device settings have SHA-256 `EE80D8B9EFD9076070EFDF26902D4D5B881A0B54FE47626CE5C79DC4703743BA`, contain `[Camera] viewing distance = 7168`, and contain no `[Terrain]` section. Pinned source establishes:

- `distant terrain = false` is the default;
- false selects `Terrain::TerrainGrid`, which displays loaded-cell terrain;
- true selects `Terrain::QuadTreeWorld` and permits the default object-paging path;
- the settings window exposes only the 2500–7168 slider when distant terrain is false and the 2500–81920 slider when it is true; and
- the accepted/current device diagnostic records `object_paging=0`.

WO36 must isolate the terrain-system transition at the same 7168 distance first. Only after `object_paging=1` is proven and the same-distance result is captured may it test 16384 and, if stable, 32768. A mere movement of the cutoff is not a correction.
