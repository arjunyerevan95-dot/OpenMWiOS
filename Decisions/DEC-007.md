# DEC-007 — Accept the WO30 Touch Baseline and Keep Renderer Causes Unproven

Status: established

## Decision / finding

Accept WO30 source commit `195f3a4bbcfd17ecd46546f3e28d3ee8558bed27` as the current engineering baseline under a **PARTIAL ACCEPT** disposition.

The accepted practical touch baseline provides a 0.75-second Menu long-press editor, deferred normal short-tap Pause dispatch, movable/resizable fixed controls, movement-radius adjustment, versioned safe-area-relative storage, live opacity adjustment, and nominal `0.20` idle opacity. The user considers this touch result satisfactory for current use apart from menu/options scrolling.

No renderer correction is accepted. WO30 did not prove the earliest invalid R1 foliage/particle alpha boundary or R2 distance/fog/horizon boundary and correctly applied no speculative workaround.

## Acceptance limits

- Reset preserves the selected opacity instead of restoring nominal `0.20` as WO30 specified.
- Only the selected fixed control displays the explicit bounds ring/resize affordance; the order requested affordances on every editable fixed icon.
- Force-quit/relaunch persistence was not independently device-observed.
- No independent post-test crash inventory or complete action-control matrix was supplied.
- Menu/options scrolling remains a separate deferred touch issue.

These limits do not prevent using the implementation as the current practical touch baseline. They prevent claiming complete satisfaction of the WO30 touch matrix.

## Renderer consequence

The next renderer order must concentrate on the actual exterior defects and must not absorb touch cleanup. It should provide an app-owned, bounded record of both OpenMW intended state and GL4ES received/applied state before applying a minimal source-backed correction.
