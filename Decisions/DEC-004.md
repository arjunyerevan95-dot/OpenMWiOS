# DEC-004 — Reject WO28 and Keep the Observed Crash Paths Distinct

Status: established

## Decision / finding

WO28's implementation result is rejected. Its execution, CI, artifact, screenshot, and user-observation records are accepted as evidence, but the candidate does not become accepted engineering state. WO27 remains the highest qualified runtime baseline, and WO28 is superseded.

The following user-observed failures are separate investigative paths unless later crash or termination evidence proves that they converge:

1. intermittent immediate launch-time hard crash, including several consecutive failed launches before a later attempt reaches the menu;
2. immediate hard crash after selecting `New Game` from a successfully reached menu;
3. immediate hard crash after activating any tested touch-overlay button from a successfully reached menu.

No new engineering work is authorized by this decision. A future investigation requires a new canonical `READY` work order and a separate explicit orchestrator start directive.

## Why it matters

Fast Development compilation, packaging, and visible main-menu rendering do not satisfy WO28's runtime acceptance criteria. Preserving the three observations independently prevents an unproven single-cause theory from narrowing a later crash investigation prematurely.

- Candidate source `1dc819cea447f8ac40c878e1a6d7f4d478e94063`.
- Fast Development run `32511443555` succeeded and produced artifact `OpenMW-iOS-fast-30` (artifact ID `9457442141`).
- [WO28 execution completion record](../Evidence/WO-028/completion.md).
- [WO28 evidence manifest](../Evidence/WO-028/manifest.md).
- User observations recorded on 2026-08-22.
- No crash report, termination report, jetsam report, or symbolicated stack was supplied.
- The installed binary identity was not independently read back from the device.

## Environmental context

Before this IPA was sideloaded, SideStore reported that its own certificate was no longer valid. The user re-signed SideStore and then sideloaded OpenMW. This relationship is unknown and remains environmental evidence only. It must not be treated as causal unless later evidence implicates signing, entitlements, dyld, provisioning, or installation state.

## Applies to

- Canonical disposition of WO28.
- Scoping and hypothesis control for any later crash-capture/root-cause work.
- Preservation of the user-requested icon-opacity change as deferred UX evidence rather than active scope.

## Does NOT establish

- That all three crash paths share one root cause.
- That SideStore, signing, provisioning, entitlements, dyld, or installation state caused a crash.
- The exact installed binary identity on the tested device.
- A crash mechanism, stack, offending thread, or corrective patch.
- Authorization to change runtime, source, build behavior, or icon opacity.

[WO-028](../WorkOrders/WO-028.md) as an executable work order. The rejected candidate and its evidence remain preserved in Git history and `Evidence/WO-028/`.
