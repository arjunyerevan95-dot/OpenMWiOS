# DEC-018 — Adopt the Zink foundation for direct touch-control integration

- Status: **ACCEPTED DIRECTION; INTEGRATED RUNTIME NOT YET QUALIFIED**
- Date: 2026-10-31
- Applies to: WO39 closure and [WO-040](../WorkOrders/WO-040.md)
- Supersedes: DEC-017's prescribed GL4ES capture-contract prerequisite, not its historical findings

## Decision and user authority

Use joedemo42/OpenMW release `v0.52-149`, exact source `2931be63bd2147e437a2b077ed6c97f563648a0a`, as the selected foundation for a new iOS candidate. Port our customizable UIKit/SDL touch controls onto it, preserving its Mesa/Zink/MoltenVK renderer and pinned dependency stack.

The user explicitly accepts the reported limitations and says no preliminary device check of the old rendering defects/performance is needed, citing Reddit observations. Proceed directly to control porting. Do not recreate that waived gate as a prerequisite, insist on stock-IPA screenshots, or finish WO39 first. Record this as a user-authorized selection based on external reports, not an independently verified project rendering result.

Close WO39 as SUPERSEDED. Preserve the current repo, histories, worktrees, ControlPlane and evidence. Develop the new foundation in an isolated candidate checkout and publish only a new branch in the user's existing OpenMWiOS repository. Do not force-rebase existing branches, replace main, merge old renderer patches into the new foundation, or alter joedemo42's repository.

## Source-backed rationale

- The selected release uses desktop OpenGL through Mesa/Zink, MoltenVK and Metal, not GL4ES/OpenGLES. Its recipes pin Mesa 25.1.9, MoltenVK 1.4.2, SDL2 2.32.10, and the same OSG revision `01cc2b585c8456a4ff843066b7e1a8715558289f` as our old baseline.
- Our touch adapter is UIKit/Objective-C++ with SDL virtual-controller and fallback event input; its layout model/icons/editor/profile storage can be moved without our renderer patches.
- The donor's `apps/openmw/ios/platform.mm` currently creates a system GCVirtualController and a two-finger menu gesture. These must not compete with our overlay. Device detection, menu mode, input lifetime and overlay attachment require a deliberate adapter, not a wholesale bootstrap copy.
- This is an OpenMW 0.51-to-0.52 foundation change as well as a renderer-stack change. Old source/runtime acceptance does not transfer automatically to the new executable.

The accepted limitations include iOS 18+, desktop GL 2.1/GLSL 1.20, Mesa 25.1 compatibility pinning, a documented extra presentation frame, no working Simulator runtime, and untested free-Personal-Team signing. Do not expand WO40 into removing these limitations or redesigning graphics. Preserve notices and upstream provenance.
