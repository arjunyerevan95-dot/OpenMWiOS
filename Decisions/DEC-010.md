# DEC-010 — Accept WO31 partial localization and target late-session renderer state

- Status: **ACCEPTED**
- Date: 2026-08-23
- Applies to: WO-031 final review and WO-032 issuance

## Decision

Accept WO31 as a partial diagnostic result. Accept its execution evidence and causal narrowing, but do not accept its diagnostic source as the qualified runtime baseline and do not claim a renderer correction.

Close WO31 and issue WO32 as READY. WO32 may use the WO31 observability source as an investigation continuation baseline, but must replace broad startup sampling with target-gated late-session sampling before selecting any correction.

The accepted engineering baseline remains `195f3a4bbcfd17ecd46546f3e28d3ee8558bed27`.

## Accepted WO31 findings

### R1 — foliage and particles

- The device file contains live OpenMW, OSG, and GL4ES records and proves the production bridge resolves.
- Real defective asset families were identified and bound to GL texture names.
- Visible chimney smoke is a valid particle reproduction. The user walked around and did not cast a fire spell; therefore cast-fire behavior is not a required representative sample for this run.
- `textures/tx_smokealpha00a.dds` was bound as texture 115; additional smoke texture bindings appeared later.
- Translucent moss and fern textures were bound after the broad draw budget had already exhausted.
- All 96 recorded draws preceded the first defective binding and had `category=-1`. The applied alpha/blend/depth/shader state of a defective foliage or smoke draw remains unknown.

The unresolved R1 boundary is now narrower: defective assets reach OSG texture objects, but their representative GL4ES draw/program state was not captured.

### R2 — distance, fog, and horizon

- OpenMW intended and OSG-applied exterior fog state agree.
- GL4ES received mode `9729`, start `2007.04`, end `7168`, and color `0.960784,0.921569,0.878431,1`.
- GL4ES applied-program samples exhausted before exterior receipt and only describe early program-1 controls with no fog.
- The run supplied one repeated view-distance setting, not two materially different settings.

The unresolved R2 boundary is now after correct GL4ES fog receipt: exterior program consumption, content/culling coverage, and sky/clear/depth presentation remain unproven.

## Evidence-quality limitation

`git diff --check 8140aa4..626b332` reports trailing whitespace on blank added lines embedded in the OpenMW/GL4ES dependency patch payloads. This does not alter the device conclusion, but the patch-format defect must be removed before the diagnostic source is accepted into any final patch series.

## WO32 direction

WO32 must:

- gate R1 draw sampling on dynamically identified defective texture/category bindings rather than record early `category=-1` draws;
- gate R2 applied-program sampling until exterior fog receipt/state application is active;
- capture two materially different view-distance settings;
- use visible foliage and chimney smoke as the required R1 cases, with a cast fire spell optional;
- inspect distance/culling/sky/clear/depth state if fog consumption is correct;
- make no touch changes;
- apply no renderer correction until the first invalid applied boundary is proven.
